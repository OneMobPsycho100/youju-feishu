# 报销统计

## 部门与员工消耗分析

“报销统计”统一提供“报销金额／预算消耗”切换。默认仍为本月、最终已通过的报销金额；两种口径共用公司、日期、申请部门、员工和费用类别筛选，部门与员工条件取交集。

报销金额继续使用原审批的申请金额、提交时间、主体范围和最终状态。预算消耗使用每单唯一预算用量，默认合计已使用、在途和冻结，已释放记录不计入。切换口径清除不适用状态，保留仍有效的部门、员工、类别和日期；缺少归属或提交时间的占用暂不计入消耗并显示完整性提示。

部门和员工排行使用横向条形图，展示金额前10项；点击部门选择该部门并展示员工排行，点击员工进入个人类别和趋势分析。同名员工按稳定身份区分，完整分组在下方表格按部门、员工、类别切换。部门按当前公司范围内保存的申请部门名称分组。

费用类别使用环形图，金额、单数和占比可悬停查看，点击扇区或图例查看对应明细，也可用键盘Enter或空格打开。预算消耗趋势以已使用、在途、冻结三色堆叠，按申请提交日期展示当前用量分布，不表示当时历史余额；点击日期下钻明细，月份下钻范围会裁剪到原筛选起止日期。

尚未匹配预算的已归属报销也纳入总消耗，单独提示金额及单数，并提供未匹配明细入口。只要主体、部门、类别及提交日期匹配任一预算即视为已覆盖，历史分析包含已归档预算，多预算重叠不重复累计单据或金额，不汇总各预算额度。

接口组保持 `/api/v1/reimbursement-statistics`，新增 `measure=application|consumption`、`department`、`usage_state` 和 `budget_coverage`。旧请求缺省 `measure=application`；`group_by` 增加 `department`。`usage_state` 为空时包含 `USED / RESERVED / FROZEN`，仅消耗口径使用；`budget_coverage` 为 `all / matched / unmatched`，默认全部。

响应保留原字段，增加实际口径、部门选项、完整部门／员工／类别分组、消耗构成、预算覆盖及完整性提示。金额及占比由后端Decimal计算，以十进制字符串传输；前端数值转换只用于绘图尺寸。查询、下钻及导出共用条件，Excel注明口径并包含统计说明、分组汇总、类别汇总、趋势和审批明细，消耗明细附占用状态和预算覆盖。无需新增数据库迁移或图表依赖。

侧栏“报销统计”进入 `#/statistics`。管理员、财务和只读用户均可查询、查看原审批及导出。默认选择本月1日至今天、最终审批状态“已通过”，日期使用北京时间。

## 筛选与统计口径

- 支持日期范围，以及本月、上月、近30天、今年快捷选择。报销人、报销类别均可搜索和多选，留空表示全部；顶部公司主体条件同步生效。
- 日期取飞书实例的申请提交时间 `start_time`，包含起止日期全天，独立于工作台采集时间。不能用预审 `PASS` 代替最终实例 `APPROVED`。
- 每张已同步审批计一次申请总额，多张附件、多个公司主体不会增加全局单数。指定主体时包含归属该主体的整单金额，不按主体分摊，各主体金额不能直接相加作为企业总额。
- 单独导入的历史发票不具备完整报销申请信息，不单独计为报销单。统计结果不代表付款或入账结果。
- 完整分组表可按部门、报销人、费用类别切换，按金额降序展示并分页；部门／员工条形图展示金额前10项。类别环形图和趋势图独立展示，支持悬停、点击和键盘下钻。占比以当前筛选总额为分母，总额为零时显示零；环形图不绘制虚假的等分扇区，并显示暂无金额占比。
- 90天以内按日展示趋势，超过90天按月展示，空周期补零。金额由后端 Decimal 精确累计，接口传输十进制字符串，页面不重新求和。
- 报销人按飞书 open_id 区分，同名人员保留不同身份；只取得 user_id 时使用 `user_id:` 前缀。本地已有姓名优先展示，未解析姓名时显示已有申请人信息或身份编号。

## 历史数据补齐

数据库迁移 `0008_reimbursement_statistics` 新增可空的 `submitted_at`、`applicant_id` 和查询索引。新单同步直接采集统计元数据；历史单在后台每轮最多安排20个逐单幂等任务。首次启动即调度，之后使用部署环境 `SYNC_INTERVAL_SECONDS`（默认5分钟）。元数据补齐独立于工作台中的自动增量补偿同步配置，关闭自动补偿或调整其间隔不改变元数据补齐调度。

任务类型为 `REIMBURSEMENT_METADATA`，界面名称“报销统计元数据补齐”。任务只读取飞书实例元数据，单据分别提交，不下载原件、不执行预审或审批回写，也不改变审核版本。任务错误沿用既有重试规则，失败后财务或管理员可从“后台任务”手动重试；一条失败不阻断其余记录。

未取得提交时间的记录暂不纳入日期统计，页面显示符合其他条件的“提交时间待补齐”单数。已取得时间但缺少人员身份的旧单，临时按原申请人字段归组，明确标注“身份待补齐”；补齐后归入对应真实身份。演示模式对新旧演示单保存模拟提交时间及稳定人员身份，并在页面和导出中说明模拟口径。

## 明细与导出

点击分组查看分页审批明细，也可查看当前条件的全部明细；再点击申请打开既有审批详情抽屉。关闭抽屉保留统计筛选；变更筛选或分组维度关闭旧明细。

页头“导出 Excel”下载当前筛选下的完整报表，包含“统计说明、分组汇总、类别汇总、趋势、审批明细”五张表，不受明细分页或下钻影响。超过50,000单会明确提示缩小范围，不截断导出。金额按两位小数文本保存，编号及用户文字明确保存为文本，避免长编号、金额精度损失或被识别成公式。

## HTTP 接口

全部接口使用现有登录会话，未登录返回401。`/api/docs` 提供中文字段说明。

| 方法与地址 | 作用 |
| --- | --- |
| `GET /api/v1/reimbursement-statistics` | 总指标、分组、趋势和完整性提示 |
| `GET /api/v1/reimbursement-statistics/options` | 当前主体与口径下的部门选项，以及所选部门的人员和类别选项 |
| `GET /api/v1/reimbursement-statistics/details` | 当前范围或指定分组的分页审批明细 |
| `GET /api/v1/reimbursement-statistics/export` | 当前筛选的完整 Excel 报表 |

公共参数为 `company_id`、`start_date`、`end_date`、`applicant_ids`、`expense_types`、`status`、`measure`、`department`、`usage_state` 和 `budget_coverage`。日期格式为 `YYYY-MM-DD`，缺省为本月1日至今天；开始日期晚于结束日期返回中文422错误。人员和类别重复传参实现多选，例如：

```text
/api/v1/reimbursement-statistics?start_date=2026-10-01&end_date=2026-10-28&applicant_ids=ou_a&applicant_ids=ou_b&expense_types=差旅费&status=APPROVED&group_by=applicant
```

`status` 缺省为 `APPROVED`，显式 `status=` 表示全部；其他可选状态为 `PENDING / REJECTED / CANCELED / REVERTED / DELETED`。前端不得省略空状态参数。

汇总及导出通过 `group_by=expense_type|applicant|department` 选择维度。明细下钻时传入 `group_by` 和汇总返回的 `group_key`，不能使用显示名代替真实分组标识；不传分组条件则查询全部明细。分页默认每页20条，最大100条。

响应包含实际 `scope`、总指标、三种完整分组、补零趋势、提交时间与归属缺失提示、`pending_identity_count` 和演示标识。筛选选项按主体、口径和部门联动，不随日期或审批状态收窄。
